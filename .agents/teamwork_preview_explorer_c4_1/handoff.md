## 2. Logic Chain

1. From Observation 1 and Observation 5: The database schema and JPA entity enforce `courses.created_by` as `NOT NULL REFERENCES app_users(id)`.
2. From Observation 2 and Observation 3: In `V107__Seed_1C_Course_And_Curator.sql`, the course insertion subquery `(SELECT id FROM app_users WHERE role = 'ADMIN' ORDER BY id ASC LIMIT 1)` attempts to find an admin user.
3. Because no migrations before V107 create an admin user, and V107 only seeds a `CURATOR` user, `(SELECT id FROM app_users WHERE role = 'ADMIN'...)` returns `NULL` on any fresh database.
4. Attempting to insert `NULL` into `courses.created_by` triggers PostgreSQL error `null value in column "created_by" of relation "courses" violates not-null constraint`.
5. On a clean database running Flyway sequentially from V1, this causes migration V107 to fail, preventing subsequent migrations from running.
6. On production/existing instances, an ADMIN user had already been seeded by runtime seeders before V107 was applied, so V107 succeeded on those instances with a valid admin id.
7. From Observation 4: The latest migration file in the repository is `V118__Rollback_Payments.sql`.
8. Any subsequent migration created for schema adjustments must be version `V119__*.sql`.

---

## 3. Caveats

- Migrations V1 through V118 cannot be modified in place because Flyway checksum validation (`validate-on-migrate=true`) is active in production.
- Existing production databases already have V107 applied with a non-null `created_by` (associated with the existing ADMIN user). There are no rows in production with `created_by IS NULL` in `courses`.
- A migration `V119` cannot retroactively fix a failure at `V107` during sequential V1-to-V119 execution on a clean DB unless baseline configuration or environment setup (e.g. `baseline-version=118` on environments where baseline is used, or pre-populating admin in migrations if baseline is not used) is aligned.

---

## 4. Conclusion

- **Root Cause Confirmed**: In `V107__Seed_1C_Course_And_Curator.sql` line 13, `(SELECT id FROM app_users WHERE role = 'ADMIN' ORDER BY id ASC LIMIT 1)` evaluates to `NULL` on an empty/fresh database because no ADMIN user exists in `app_users` prior to or during V107.
- **Constraint Violation**: Inserting `NULL` into `courses.created_by` violates the `NOT NULL` constraint defined in `V14__Courses_Schema.sql`.
- **Migration Numbering**: The next migration must be `V119` (not V111 as initially estimated in early audit notes, because V111–V118 already exist in the codebase).
