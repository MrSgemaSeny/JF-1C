# Стандарты разработки и регламент (CONTRIBUTING.md)

Документ устанавливает ключевые правила, архитектурные принципы и регламент написания кода для команды разработки JF-1C.

---

## 1. Архитектурные принципы (KISS / YAGNI)

* **Борьба с оверинжинирингом**: На текущем этапе развития SaaS-платформы приоритетом является надежность, простота поддержки и скорость доставки бизнес-фичей. Избегайте преждевременной абстракции там, где достаточно лаконичного модульного кода.
* **Принцип менторства и прозрачности**: Любое архитектурное решение сопровождается объяснением "ПОЧЕМУ", а не только "ЧТО".

---

## 2. Критические неизменяемые правила

1. **Неизменяемость Flyway-миграций**: Категорически запрещено редактировать уже примененные файлы миграций в `db/migration/` (файлы `V1`..`V108`). Любое добавление колонок или таблиц делается строго новыми файлами (`V109`, `V110` и т.д.).
2. **Секреты и ключи**: Запрещено хардкодить пароли, JWT-ключи и токены в исходных файлах. Все секреты передаются исключительно через переменные окружения и GitHub Secrets.
3. **Операции с БД при старте**: Заполнение первичных данных (сидинг) производится строго через `@EventListener(ApplicationReadyEvent.class)`. Использование `@PostConstruct` для работы с БД запрещено.
4. **Запрет на `flywayClean`**: Запрещено выполнять чистку базы `flywayClean` на любых стендах кроме локальной одноразовой тестовой БД.
5. **Тесты перед отправкой в репозиторий**: Запрещено пушить код в гиты при наличии падающих тестов бэкенда (`./gradlew test`) или фронтенда (`npx vitest run`).
6. **Политика Emojis**: В коде, документации, комментариях и коммит-сообщениях строго запрещено использование `emojis`.

---

## 3. Правила Git Workflow

* **Политика коммитов**: Не создавать мелкие хаотичные коммиты без необходимости (минимальный объем изменений ~40+ строк кода или явное завершение фичи/багфикса).
* **Формат сообщений коммитов**:
  * `feat(crm): add export to excel for client tasks`
  * `fix(auth): handle refresh token expiration cleanly`
  * `docs(onboarding): update environment setup instructions`

---

## 4. Требования к коду

### Backend (Spring Boot 3 / Java 17):
* Обработка исключений строго через `GlobalExceptionHandler` с возвратом понятного `requestId`.
* Проверка прав доступа: сочетание `@PreAuthorize` и проверками в `CrmAccessService`.

### Frontend (React 19 / TypeScript):
* Соблюдение слоев FSD (`shared` -> `entities` -> `features` -> `widgets` -> `pages`).
* Все тексты интерфейса выносить в локализацию `i18n`.
* Работа с API только через единый клиент `@/shared/api/http`.
