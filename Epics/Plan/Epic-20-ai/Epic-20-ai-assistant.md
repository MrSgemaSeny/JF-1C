## Зачем этот эпик

Три роли платформы имеют принципиально разный контекст и разные потребности в ИИ-помощи:

- **LEARNER** не понимает материал курса — ИИ объясняет тему урока, отвечает на вопросы, проверяет понимание. Изолировано от бизнес-данных, низкий риск.
- **CLIENT** не понимает свою бухгалтерию — ИИ объясняет документы, статусы задач, проводки на его данных. Требует IDOR-контроля.
- **EMPLOYEE** тратит время на рутину — ИИ автоматизирует разбор выписок и заполнение шаблонов по данным из 1С. Высокий риск, требует изоляции и аудита.

Реализация поэтапная: Фаза 1 → Фаза 2 → Фаза 3. Каждая фаза независима.

## Out of Scope

- ИИ для ADMIN и ADVISOR — не планируется
- Обучение или файн-тюнинг модели на данных компании — вне скоупа
- Голосовой интерфейс — вне скоупа
- RAG по всей базе документов клиентов — вне скоупа (слишком высокий риск утечки)

## Технические решения

### Модель
- **Groq API** (ADR-004) — низкая латентность, критично для чата в плеере курса
- Модель: `llama-3.1-8b-instant` для быстрых ответов; `llama-3.3-70b-versatile` для сложных запросов по документам
- Ключ только в env vars: `GROQ_API_KEY`

### Фаза 1 — LEARNER (изолированный контекст)

Контекст запроса = только содержимое текущей главы курса. Никаких бизнес-данных.

```
System prompt:
"Ты — ИИ-тьютор курса по бухгалтерии. Отвечай только по теме текущего урока.
Контекст урока: {chapter.content}
Язык ответа: {user.locale}"
```

- Бэкенд: новый эндпоинт `POST /api/lms/chapters/{chapterId}/ai-ask`
- Авторизация: `@PreAuthorize("hasRole('LEARNER')")` + проверка что глава принадлежит enrolled курсу
- Rate limit: 20 запросов/час на пользователя (Bucket4j, отдельный бакет)
- Фронтенд: чат-виджет в `CoursePlayerPage.tsx`, сворачиваемый

### Фаза 2 — CLIENT (контекст его данных)

Контекст запроса = только данные текущего клиента (его задачи, документы, инвойсы).

```
System prompt:
"Ты — помощник клиента бухгалтерской компании ZhanFinance.
У тебя есть доступ только к данным этого клиента.
Клиент: {client.companyName}
Данные: {sanitized_client_context}
Не раскрывай данные других клиентов. Не давай юридических советов."
```

- [WARNING] Контекст клиента формируется на бэкенде — фронтенд не передаёт сырые данные
- Бэкенд: `POST /api/client-portal/ai-ask` — сервис сам подтягивает данные по `clientId` из токена
- IDOR-защита: `clientId` берётся исключительно из JWT, не из тела запроса
- Аудит: каждый запрос логируется в `audit_log` (кто спросил, что спросил, timestamp)
- Rate limit: 10 запросов/час на клиента

### Фаза 3 — EMPLOYEE (автоматизация рутины)

- [CRITICAL] Доступ к данным 1С только после реализации Epic-13 (OData интеграция)
- Выписка загружается как файл → парсится на бэкенде → передаётся в Groq как структурированный контекст
- Результат возвращается как предложение (не применяется автоматически) — сотрудник подтверждает вручную
- Полный аудит-лог всех ИИ-действий обязателен

## Acceptance Criteria

### Фаза 1
- [ ] [US-20.1] LEARNER может задать вопрос в плеере курса и получить ответ в контексте текущей главы
- [ ] [US-20.2] ИИ может задать контрольный вопрос по теме главы и оценить ответ
- [ ] Запросы за пределами темы урока отклоняются или перенаправляются
- [ ] Rate limit 20 req/час работает, при превышении — понятное сообщение пользователю
- [ ] Ключ Groq только в env vars, не в коде и не в логах

### Фаза 2
- [ ] [US-20.3] CLIENT получает объяснение своих данных без доступа к чужим
- [ ] [US-20.4] Конкретный инвойс или документ объясняется корректно
- [ ] clientId берётся из JWT, не из запроса — проверено тестом
- [ ] Каждый запрос записан в audit_log
- [ ] Rate limit 10 req/час на клиента

### Фаза 3
- [ ] [US-20.5] Выписка парсится и возвращаются предложения по проводкам
- [ ] [US-20.6] Шаблон документа заполняется по данным задачи
- [ ] Результат ИИ применяется только после явного подтверждения сотрудником
- [ ] Полный аудит всех ИИ-операций

## Известные ограничения / технический долг

- `[INFO]` Фаза 3 заблокирована Epic-13 (1С OData) — не начинать до его завершения
- `[WARNING]` Контекст клиента в Фазе 2 необходимо тщательно санировать перед передачей в Groq — персональные данные не должны уходить в промпте в сыром виде
- `[INFO]` Groq имеет лимиты на бесплатном тире — заложить платный тир при росте нагрузки
- `[INFO]` История чата не хранится между сессиями — каждый запрос stateless. Если понадобится история — отдельный эпик
