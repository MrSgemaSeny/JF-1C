## Зачем этот эпик

Знать о проблемах раньше пользователей. Эпик обеспечивает полную видимость (observability) работы системы, отслеживание ошибок, мониторинг доступности и моментальное оповещение команды при падениях или деградации сервисов.

## Out of Scope

- Распределение логов в централизованный кластер (Loki / ELK)
- Автоматическое масштабирование инфраструктуры на основе метрик (KEDA / HPA)

---

## Технические решения

- **OTLP PUSH модель вместо Prometheus scraping** — так как эндпоинт `/actuator/prometheus` защищен JWT и недоступен для внешнего скрейпинга Prometheus, используется отправка метрик по OTLP (OpenTelemetry Protocol) PUSH модели.
- **Actuator endpoints и Micrometer** — подключен `micrometer-registry-prometheus` и настроены эндпоинты Spring Boot Actuator (`health`, `info`, `metrics`, `prometheus`) для экспорта метрик работы приложения.
- **Внешний UptimeRobot и мультиплатформенный алертинг** — интеграция с UptimeRobot для непрерывного uptime-мониторинга с отправкой мгновенных уведомлений о падении сервиса в Telegram и Email.

## Известные ограничения / технический долг

- Backend Sentry SDK временно отключен из-за бага совместимости Sentry SDK и Spring Boot 4.1.
- Эндпоинт `/actuator/prometheus` закрыт JWT и не может быть использован для внешнего скрейпинга (решено переходом на OTLP PUSH).
