## Зачем этот эпик

Выкатывание изменений напрямую на продакшн без предварительной проверки создает риски сбоев в работе сервиса. Эпик создает изолированное staging-окружение с отдельной базой данных и автоматизированным CI/CD пайплайном, что позволяет тестировать функциональность и прогонять smoke-тесты до деплоя на прод.

## Out of Scope

- Нагрузочное тестирование staging-сервера
- Автоматическое копирование и маскирование реальных данных с продакшна в staging
- Поддержка динамических ephemeral-окружений под каждый pull request

---

## Технические решения

- **Staging app на Fly.io** — отдельное изолированное приложение zhanfinance-staging.fly.dev с конфигурацией, повторяющей продакшн.
- **Изолированная база данных** — выделенный экземпляр PostgreSQL для staging-среды во избежание изменения или повреждения продуктивных данных.
- **Двухэтапный деплой через GitHub Actions** — автоматический деплой веток develop на staging и ограниченный деплой в main только при успешном прохождении staging-этапа.
- **Автоматический прогон smoke-тестов** — запуск E2E/smoke тестов на staging до выдачи разрешения на промоут приложения в продакшн.
