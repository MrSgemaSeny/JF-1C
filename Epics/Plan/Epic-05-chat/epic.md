## Зачем этот эпик

Эпик обеспечивает возможность реального (real-time) общения между пользователями различных ролей внутри платформы. Это решает проблему разрозненной коммуникации, позволяет оперативно вести диалог без обращения к сторонним мессенджерам и сохраняет всю историю сообщений в едином контексте системы.

---

## Пользовательские истории

| ID       | Роль      | Хочу                                      | Чтобы                                              | Статус |
|----------|-----------|-------------------------------------------|----------------------------------------------------|--------|
| US-05.1  | ALL       | отправлять и получать сообщения в реальном времени | общаться с пользователями без задержек и перезагрузки страницы | Done   |
| US-05.2  | ALL       | просматривать историю сообщений            | иметь доступ к ранее отправленным сообщениям и контексту беседы | Done   |

---

## Out of Scope

- Push-уведомления о новых сообщениях в чате
- Передача файлов и медиавложений внутри чата
- Групповые чаты и каналы

---

## Технические решения

- **WebSocket через STOMP** — обеспечение двухстороннего real-time обмена сообщениями между клиентом и сервером
- **Таблица chat_messages** — структура базы данных для персистентного хранения истории сообщений

---

## Acceptance Criteria

- [x] [US-05.1] Сообщения доставляются в режиме реального времени без перезагрузки страницы
- [x] [US-05.2] История сообщений сохраняется в базе данных (таблица chat_messages) и загружается при открытии чата

---

## Definition of Done

- [ ] Все US из таблицы выше реализованы или явно перенесены в другой эпик с указанием куда
- [ ] Flyway-миграции добавлены и проверены на чистой БД
- [ ] Smoke-тесты покрывают happy path каждой US
- [ ] Секреты только в env vars / Fly secrets, не в коде
- [ ] Нет raw stack trace в ответах API (ошибки через ApiException + ErrorCode)
- [ ] CI/CD pipeline зелёный (все тесты проходят перед деплоем)
- [ ] Эпик задеплоен на прод и проверен вручную

---

## Известные ограничения / технический долг

- `[INFO]` Реализация WebSocket требует поддержания постоянного соединения между клиентом и сервером; обработка разрывов сети производится на стороне клиента.
