## Зачем этот эпик

Создание двустороннего интеграционного шлюза между платформой ZhanFinance (CRM/Portal) и базой данных «1С:Бухгалтерия для Казахстана 8.3». Без этого эпика клиенты не могут видеть оперативные финансовые показатели (сальдовые ведомости, остатки на счетах 1030/1210/3310, ОСВ), вынуждены вручную запрашивать акты сверок и счета, а бухгалтеры тратят часы на ручное дублирование проводок и выбивание фискальных чеков.

## Out of Scope

- Прямое редактирование конфигурации 1С на стороне CRM (все изменения идут только через стандартный OData API или подключаемое расширение `.cfe`).
- Полный кадровый расчет больничных/отпускных внутри веб-интерфейса (выполняется в 1С, в веб отдаются только итоговые сводные ведомости).

---

## Технические решения

- **Архитектура интеграционного адаптера (Spring Boot OneCGatewayService)**:
  - Взаимодействие через стандартный OData REST интерфейс 1С:Предприятие 8.3 (`/odata/standard.odata/`) с авторизацией по системному сервисному аккаунту.
  - Кэширование тяжелых отчетов (ОСВ, агрегированные остатки) в Caffeine Cache с TTL 5–15 минут.
- **Мультитенантность и изоляция данных (CrmAccessService)**:
  - Строгая фильтрация всех OData-запросов по `Организация_Key` (БИН/ИИН организации клиента). Клиент никогда не может получить доступ к данным чужого БИН.
- **Фискальный контур (WebKassa API Client)**:
  - Интеграция с облачным API WebKassa для фискализации чеков при оплатах через Kaspi Pay / банковские карты с сохранением фискального признака и ссылки на чек ОФД в БД.
- **Генерация печатных форм (Document Engine)**:
  - Получение печатных форм (счетов на оплату, актов сверок, АВР) из 1С в формате PDF/XLSX с отдачей через Cloudflare R2 / локальный защищенный storage.

## Acceptance Criteria

- [ ] [US-21.1] Клиент в разделе «1С Отчеты» видит сальдовую ведомость с разбивкой по банку (1030), дебиторке (1210) и кредиторке (3310) за выбранный период.
- [ ] [US-21.2] Генерация акта сверки по контрагенту формирует актуальный PDF-документ с сальдо на начало и конец периода.
- [ ] [US-21.3] В архиве документов доступны накладные, АВР и платежные поручения с отметками банка/ЭЦП.
- [ ] [US-21.4] Проведение документа в 1С триггерит обновление статуса связанной задачи в CRM.
- [ ] [US-21.5] Пакетная отправка заявок из CRM создает документы «РеализацияТоваровУслуг» в 1С.
- [ ] [US-21.6] Оплата счета через платежный шлюз автоматически пробивает фискальный чек в WebKassa и прикрепляет его в личный кабинет.
- [ ] [US-21.7] В админ-панели настраиваются эндпоинты, таймауты и учетные данные OData шлюза с проверкой соединения.

## Definition of Done

- [ ] Все US реализованы и покрыты интеграционными тестами.
- [ ] Flyway-миграции для настроек подключения и фискальных чеков проверены на чистой БД.
- [ ] Секреты и пароли к 1С/WebKassa хранятся строго в переменных окружения / Fly Secrets.
- [ ] В ответах API отсутствуют raw-ошибки 1С (все ошибки обрабатываются через ApiException + ErrorCode).
- [ ] CI/CD pipeline проходит без ошибок.
