# Security Policy

## Supported Versions

We actively provide security updates and patches for the following versions:

| Version | Supported          |
| ------- | ------------------ |
| 1.x (main) | :white_check_mark: |
| < 1.0.0   | :x:                |

## Reporting a Vulnerability

The ZhanFinance (JF-1C) engineering team takes security and data privacy very seriously. If you discover a vulnerability, security flaw, or potential exposure, please follow responsible disclosure protocols:

1. **Do NOT open a public GitHub issue** for security vulnerabilities.
2. Send a detailed report directly to the security team:
   - **Email**: `muratorynbasar0@gmail.com`
   - **Subject**: `[SECURITY VULNERABILITY REPORT] - JF-1C - <Component/Vulnerability Type>`

### What to Include in Your Report:
- A clear description of the vulnerability and its potential impact.
- Step-by-step reproduction instructions or a Proof of Concept (PoC).
- Affected endpoints, modules, or parameters.
- Any suggested remediations or mitigations if available.

### Response Timelines (SLA):
- **Initial Acknowledgement**: Within 24 hours.
- **Triage & Severity Assessment**: Within 72 hours.
- **Remediation & Patch Deployment**: Critical (P0) within 7 days; High (P1) within 14 days.

## Responsible Disclosure & Scope

Please adhere to the following rules during security research:
- Do not execute Denial of Service (DoS / DDoS) attacks.
- Do not perform social engineering, phishing, or physical attacks.
- Do not attempt to access, exfiltrate, modify, or destroy real client or company financial data.
- Give the development team adequate time to remediate the issue before any public disclosure.
